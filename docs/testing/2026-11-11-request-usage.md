# 중첩 보고서 비용·토큰 집계 검증과 작업 중단 기록

날짜: 2026-11-11. 대상: 감사 5번. 수정 전 기준 커밋: `5be2769`.

## 수정과 검사

- `budget.request_scope`가 하위 보고서의 사용량을 따로 측정하면서 상위 채팅 요청에도 합산한다. 병렬 형제 작업 비용은 보고서 자체 비용에 섞지 않는다.
- `add_request_usage`는 현재 범위와 부모에 각각 한 번 집계한다. DB 비용 장부 기록은 기존처럼 실제 호출당 한 번이다.
- 요청 토큰 상한은 최상위 합계로 검사하고, 초과 상태를 현재 하위 범위와 부모에 표시한다. 범위 종료·예외 시 이전 집계 문맥을 복원한다.
- `build_report`에만 하위 범위를 적용한다. HTTP 채팅과 보고서 스트리밍의 기존 최상위 집계 시작은 유지한다. 캐시 적중에는 새 비용을 더하지 않는다.
- 신규 2개 검사: 수정 전 **2 failed**, 수정 후 통과. 실제 `build_report`·기업 그래프·SQLite와 사용량 대역을 연결해 병렬 형제 작업, 상위 합계, 보고서 단독 비용, 캐시 적중을 검사한다. 토큰 상한과 예외 후 문맥 복원도 검사한다.
- 관련 검사 **26 passed**. 전체 백엔드 **166 passed, 1 deselected, 4 warnings**, 17.17초. `git diff --check` 통과.
- 실제 LLM·외부 API·브라우저 호출은 하지 않았다. 유료 요청 시작 전에 검사하는 기존 방식이므로 이미 진행 중인 병렬 호출의 토큰을 사전 예약하는 기능은 아니다.

## 중단 이유: 재적재와 업로드 세대 이름 불일치

사용자는 문제 발견 시 멈추라고 지시했다. 다음 감사 4번을 읽던 중 이전 문서 교체 수정(`20559f7`)의 연결 경로 누락을 발견해 다음 수정에 착수하지 않았다.

- `documents.register`는 업로드 벡터의 `law_name`에 고유 `vector_name`을 저장한다. 검색은 메타데이터가 가리키는 이 이름만 허용한다.
- `core/law/ingest.py`는 컬렉션을 초기화한 뒤 업로드 조문을 다시 넣을 때 원래 `doc_name`으로 청크를 만든다. `vector_name`을 복원하지 않는다.
- 실제 `ingest.ingest(fetch=False, graph=False)`에 코퍼스·벡터 저장소 대역을 연결한 읽기용 재현에서, 검색 조건은 `upload:test-generation`, 재적재 청크 이름은 `내규`로 **불일치**했다. 실제 DB·사용자 데이터는 건드리지 않았다.
- 영향: 새 방식으로 등록한 문서는 전체 법령 벡터 재적재 후 검색 필터에서 제외된다. 초기화 후 데이터가 DB에 남아 있어도 사용자에게 검색되지 않는다.
- 이 문제는 아직 미수정이다. 다음 작업은 재적재 시 `vector_name`을 유지하는 최소 수정과 재적재→검색 회귀 테스트가 우선이다. 감사 4번의 오래된 본문 문제와 함께 연결 경로를 검사해야 한다.
