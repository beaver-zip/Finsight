# 잔여 감사 수정 검증 기록

이 문서의 최신 항목이 이전 인수인계의 중단 상태보다 우선한다. 사용자는 누락 수정 후 잔여 작업 재개를 승인했다.

## 문서 재적재 연결 누락 — 수정 완료

- 기준: `96dcc8a`. `ingest.py`에서 업로드 청크의 `law_name`을 메타데이터의 활성 `vector_name`으로 복원한다. 구형 메타데이터는 기존 문서명을 유지한다.
- 신규 매개변수 검사: 수정 전 1 failed/1 passed. 수정 후 전체 백엔드 **168 passed, 1 deselected**, 15.84초.
- 실제 Weaviate 1.32.4에서 교체→법령·업로드 전체 벡터 재적재→업로드 검색→삭제 검사 **1 passed**, 1.65초. 최초 live 실행은 테스트 코퍼스가 비어 있어 빈 배치에서 실패했고 법령 한 건이 있는 현실적인 입력으로 보완했다.
- 기존 볼륨을 연결하지 않는 임시 컨테이너·UUID 컬렉션만 사용했다. 임베딩은 고정 벡터이며 의미 품질·Neo4j 재적재 검사는 아니다.
- 전체 법령 재적재 자체의 실패 원자성은 기존 방식이다. 이번 수정은 재적재 성공 후 업로드 검색이 빠지는 회귀에 한정한다.

## 감사 4 — 실행 중 법령 본문 갱신 완료

- `LawTools`가 시작 시 코퍼스 객체를 영구 보관하던 필드를 캐시된 `load_corpus()`를 조회하는 속성으로 교체했다. 검색·확장 내에서는 한 코퍼스 스냅샷을 쓴다. 외부 호출부의 `.corpus` 접근은 유지한다.
- 같은 객체로 실제 `ingest`의 fetch/save 경로를 호출해 구본문→신본문·신규 조문·검색·참조 확장과 수집 실패 시 기존 본문 유지를 검사했다. 수정 전 1 failed, 수정 후 전체 검사 169 passed, 1 deselected.
- 법령 수집·벡터·그래프·리랭커는 대역이다. 다중 프로세스 캐시 동기화나 전체 재적재 실패 시 저장소 롤백 보장은 추가하지 않았다.

## 감사 6 — 병렬 검색 크레딧 상한 수정 완료

- 단일 프로세스에서 캐시 재확인→예산·크레딧 검사→HTTP 호출→장부·캐시 기록 전체를 semaphore(1)로 직렬화한다. 같은 검색의 대기 요청은 캐시를 재사용한다.
- 이벤트로 8개 요청의 첫 캐시 miss를 동기화했다. 수정 전 신규 검사 2 failed/1 passed, 수정 후 관련 검사 10 passed. 전체 백엔드 **172 passed, 1 deselected**, 16.67초.
- 다른 검색은 남은 1크레딧에서 1회만 호출하고 나머지는 차단되며, 같은 검색은 모두 캐시 결과를 받는다. HTTP 오류 후 잠금 해제·비용 미기록·재시도도 검사한다.
- HTTP는 MockTransport, 장부는 실제 임시 SQLite다. 실제 유료 API·다중 프로세스 원자성은 검증/지원 범위가 아니다. 외부 호출이 서버까지 도달한 뒤 연결이 끊기는 경우의 정확한 과금 복구는 원천 usage 대조가 필요하며 이번 범위에 추가하지 않았다.

## 감사 7 — 업로드 조문 ID 분리 완료

- 등록 파일명 전체를 URL 인코딩한 `upload@<file_name>:<article>` ID를 쓴다. 표시 이름과 본문은 유지하고 인용 표시는 파일명에서 복원한다. 공백·확장자 차이를 구분하고 공식 법령 ID와 분리한다.
- 기존 저장 조문의 ID는 메모리에서 변환하며 원본 JSON을 강제로 덮어쓰지 않는다. 검색 결과도 물리 벡터 이름→등록 파일명을 통해 새 조문·항 ID로 연결한다. 재적재는 변환한 ID를 사용한다.
- 구형 벡터의 물리 문서명이 여러 파일에 겹쳐 구분 불가능하면 그 이름은 검색 허용 목록에서 제외한다. 잘못된 본문을 연결하는 대신 해당 문서를 각각 재등록해야 한다. 이미 저장한 채팅의 구형 인용 ID까지 복구하지는 않는다. 현재 로컬 등록 저장소는 없으며 사용자 데이터 마이그레이션은 실행하지 않았다.
- 수정 전 신규 충돌 검사 1 failed. 이후 기본 전체 **174 passed, 1 deselected**, 16.52초. 실제 Weaviate 검사 **1 passed**, 1.78초: 교체·재적재·삭제, 공백 차이 문서, 공식 법령과 같은 이름 업로드의 조문·본문 연결을 확인했다.
- 대소문자만 다른 파일의 동시 저장은 호스트 파일시스템 제약을 따르며, 파일명 정규화 자체의 충돌 정책은 별개다.

## 감사 8 — 서버 저장 파일명을 후속 적재에 전달

- 업로드 요청·응답 해석을 `src/api/documents.ts`로 분리하고, UI의 다음 단계는 로컬 File 객체 대신 서버의 `uploaded: string[]`를 전달한다. 서버가 `a:b.pdf`를 `a_b.pdf`로 바꿔도 그대로 `/rag/register`에 전달한다.
- 새 의존성 없이 Node 내장 test runner와 이미 설치된 Vite의 TS 변환을 사용한다. `npm test`와 CI 프론트 검사 단계를 추가했다.
- 프론트 API 검사 **2 passed**(변경 파일명·일반 파일·부분 거절, HTTP 400 전체 거절). `npm run build` 성공. API fetch는 대역이며 실제 브라우저 왕복은 후속 UI 검사에서 확인한다.

## 감사 10 — 로컬 DB 포트 범위 제한 완료

- Weaviate HTTP/gRPC와 Neo4j HTTP/Bolt 공개 포트 4개를 `127.0.0.1`에 바인딩한다. 컨테이너 내부 포트 및 backend의 서비스명 기반 주소는 유지한다.
- `docker compose config --no-env-resolution --format json`을 파싱해 네 포트의 `host_ip`, 외부·내부 포트와 backend 연결 주소를 검증했다. `.env`의 비밀값을 해석하거나 출력하지 않았다.
- 실제 사용자 컨테이너를 재생성하거나 볼륨을 수정하지 않았다. 실행 중인 기존 컨테이너에는 다음 재생성 때 반영된다. Neo4j 실접속·다른 기기의 접근 차단은 실행하지 않았다.

## 감사 11 — 단일 구현 캐시 추상 클래스 제거 완료

- 전체 Python 호출부를 검색해 SQLiteCache만 사용함을 확인하고 `CacheBackend`, ABC 관련 import·상속만 제거했다. SQLite 동작과 인터페이스·비용 장부는 유지한다. 소스 25줄 순감소.
- 전체 백엔드 **174 passed, 1 deselected**, 17.35초. 최초 저장소 루트에서 경로 없이 실행한 검사는 앱 import 경로가 없어 수집 오류가 났고, 지침대로 `backends/`에서 재실행해 통과했다.
- 새 테스트는 추가하지 않았다. 기존 실제 SQLite 캐시·만료·장부 및 서비스 경로 검사를 사용했다.

## 감사 9 — 최종 이벤트 없는 스트림 종료 처리 완료

- 기존 SSE 읽기를 `src/api/chatStream.ts`로 분리했다. final/interrupt/치명 오류 이전 EOF는 예외로 처리해 기존 hook의 오류 콜백으로 전달한다. 부분 오류는 최종 이벤트를 기다리고 사용자 취소는 실패로 표시하지 않는다.
- CRLF와 UTF-8 청크 분할을 처리하고 종료 이벤트 뒤 후속 이벤트는 무시한다. reader는 종료·예외 시 취소하고 잠금을 해제한다.
- 옮긴 기존 구현에서 새 검사 3 failed/1 passed를 확인했다. 수정 후 프론트 **6 passed**(업로드 2 + 스트림 4), TypeScript·Vite 빌드 성공. 새 의존성은 없다.
- 실제 Chrome/Playwright 화면에서 `a:b.pdf` 업로드→서버 `a_b.pdf` 응답→적재 요청의 `file_name=["a_b.pdf"]`→완료 화면을 확인했다.
- 같은 화면에서 progress만 보내고 끝나는 SSE를 주입해 오류 문구 표시와 로딩 말풍선 제거를 확인했다. 스크린샷 `output/playwright/early-eof.png`를 읽어 화면도 확인했다. API 응답은 브라우저 route 대역이며 실서비스/유료 API 통합 결과는 아니다.
- CLI 세션 연결 문제를 해결하는 과정에서 여러 실행 시도가 있었으며, 성공한 실제 화면 검사와 단위 검사만 위 결과로 기록했다. 브라우저 로그·스크린샷은 개인 `.git/info/exclude`에 제외했다.
