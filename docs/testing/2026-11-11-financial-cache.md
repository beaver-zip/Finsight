# 재무 캐시 갱신 회귀 검증

날짜: 2026-11-11. 대상: 감사 1번. 수정 전 기준 커밋: `c82e399`.

## 변경과 정책

- `financials.get_snapshot`의 정상 응답은 1시간, 빈 응답(013 또는 빈 목록)은 5분 캐시한다. 연결(CFS) 우선·별도(OFS) fallback과 금액·분기 계산식은 유지한다.
- `history.quarterly_history`는 조회 범위 전체의 정기보고서 목록을 한 번 읽고, 각 기간의 최종 접수번호를 `_snap`에 전달한다. 과거 기간도 정정 확인 대상이다. `cumulative_items`도 제공된 스냅샷이 없는 기간에 같은 확인을 한다.
- 기존 `original.periodic_reports`의 기간 매핑을 재사용한다. 목록 조회가 실패하면 기존처럼 이용 가능한 재무 스냅샷으로 계속 처리한다.
- 알려진 정정 접수번호와 캐시된 행의 접수번호가 다르면 만료 전에도 재조회한다. 동종기업 지표 등 접수번호를 전달하지 않는 호출도 공통 1시간 만료를 적용받는다.
- `dart.fin.v2` 공간으로 전환해 기존 `dart.fin`의 무기한 빈 응답·정상 응답을 재사용하지 않는다. 기존 SQLite 데이터나 비용 장부는 삭제하지 않는다.

## 검사

`tests/test_financial_cache.py`는 실제 프로젝트 모듈과 테스트별 임시 SQLite를 사용하며 DART 응답만 대체한다. 시간은 고정 시계로 제어해 실제 대기 없이 만료 경계를 확인한다.

- 수정 전 첫 7개: **6 failed, 1 passed**. 빈 응답 영구 잔존, 접수번호 없는 정상 캐시의 영구 재사용, 기존 빈 캐시 잔존, 이력·누적 호출에서 정정 누락을 재현했다. 명시적인 접수번호 비교 자체는 원래 통과했다.
- 최종 전체 `.venv/bin/python -m pytest -q`: **146 passed, 1 deselected, 4 warnings**, 16.72초. 기존 SWIG/fitz 경고와 asyncio fixture 설정 경고는 유지한다.
- `git diff --check`: 통과.
- 최종 관련 검사: `pytest -q tests/test_financial_cache.py tests/test_original.py` → **19 passed**.
- 정상 캐시 적중·정정 갱신·빈 응답 만료·기업/기간별 분리·기존 캐시 전환·CFS/OFS 전환·조회 장애·원천 반영 지연을 검사한다.
- 실제 보고서 목록 파싱과 이력 경로를 함께 호출해 여러 기간의 접수번호 매핑과 캐시 재사용을 검사한다. 원문 fallback과 기존 분기 손익 계산 검사도 통과했다.

## 보장 범위와 한계

- DART 실서비스를 호출하지 않았다. 실제 공시의 반영 시점이나 원천 응답 품질을 검증한 결과는 아니다.
- 공시 목록은 기존 1시간 캐시와 장애 시 만료 캐시 fallback을 유지한다. 정정이 등록되는 즉시 감지한다고 보장하지 않는다.
- 이미 빈 응답을 캐시한 기간은 새 접수번호를 알더라도 최대 5분의 빈 캐시 기간이 남을 수 있다. DART 재무 API 반영이 늦으면 반환된 실제 접수번호를 유지하며 다음 조회에서 재시도한다.
- 캐시 공간 전환 직후 최초 조회와 이후 만료 시 DART 호출량이 늘어난다. 기존 무기한 데이터의 자동 정리와 동시 요청 병합은 추가하지 않았다.
- 완성 보고서 API의 별도 캐시나 호출자가 직접 제공한 스냅샷은 강제 갱신하지 않는다. 이번 범위는 원천 재무 스냅샷 캐시와 그 이력 호출 경로다.
- 프론트 코드·의존성은 수정하지 않았으며 프론트 빌드와 Weaviate 검사는 이번에 반복하지 않았다.
