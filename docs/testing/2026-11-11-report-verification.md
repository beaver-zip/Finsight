# 보고서 검증 장애 회귀 검사

날짜: 2026-11-11. 대상: 감사 2번. 수정 전 기준 커밋: `c7f7c3e`.

## 변경 정책

- 검증 예외로 `verification=None`이면 `writer.finalize`가 생성 초안 전체(제목 포함)를 숨긴다. 기존 렌더러가 계산된 핵심 수치·표·차트와 자료 목록을 제공한다.
- 검증 불합격이면 기존처럼 근거 문제가 남은 블록·제목만 제거·대체한다. 문체 문제만 있는 블록은 기존 정책대로 유지한다.
- 검증 장애와 불합격은 HTML 상단 경고 및 JSON의 `errors`로 표시한다. SSE는 기존 PARTIAL 오류 이벤트와 경고를 포함한 최종 HTML을 전달한다.
- 캐시 조건을 공유한다. 초안 존재 + 검증 결과 존재 + `passed=True` + 토큰 상한 미초과일 때만 7일 캐시한다. HTML·JSON·채팅의 `build_report`와 SSE가 같은 조건을 사용한다.
- 보고서 캐시 버전을 `v2.3`에서 `v2.4`로 올려 이전 정책의 미검증 캐시가 반환되지 않게 한다. 기존 캐시 DB나 비용 장부를 삭제하지 않는다.

## 실행 검사

`tests/test_report_verification.py`는 실제 기업 LangGraph의 본문 작성→검증→재작성→조립 흐름을 호출한다. 외부 수집·분석 입력·LLM 응답만 대체하고, 실제 FastAPI HTML/JSON/SSE 경로와 테스트별 SQLite 캐시를 사용한다. 폰트 서브셋 생성은 이 테스트에서 생략한다.

- 수정 전 최초 12개: **8 failed, 4 passed**. 검증 장애 시 초안 노출, 불합격 경고 부재, 미검증·불합격 보고서 캐시 재사용을 재현했다.
- 최종 전체 `.venv/bin/python -m pytest -q`: **164 passed, 1 deselected, 4 warnings**, 18.71초. 기존 SWIG/fitz 및 asyncio fixture 설정 경고는 유지한다.
- `git diff --check`: 통과.
- 최종 신규 검사: **18 passed**. 검증 성공·불합격·예외, 토큰 상한, 재작성 후 검증 장애, 기존 캐시 버전 제외, HTML/JSON/SSE 간 정상 캐시 공유를 검사한다.
- 기존 본문·렌더링 검사와 신규 최초 12개를 함께 실행: **44 passed**. 이후 추가한 6개는 신규 검사 및 최종 전체 검사에 포함한다.
- 응답을 두 번 요청해 미검증·불합격·토큰 상한에서는 재생성하고 성공 시에는 캐시가 사용되는지 검사한다. 장애 시 생성 문장이 사라지고 계산된 수치와 경고가 남는지 확인한다.

## 한계와 영향

- 실제 LLM·DART·브라우저·Weaviate 연동은 이번에 실행하지 않았다. 검증기의 판단 정확도나 보고서 시각 품질을 평가한 결과는 아니다.
- 계산된 수치·표·차트는 문장 검증과 별개다. 문장 검증 장애 시 제공한다는 정책이며 원천 자료 자체가 정확하다는 보장은 아니다.
- 미검증 또는 불합격 보고서는 재요청할 때 재생성하므로 LLM 호출·비용이 늘 수 있다. 버전 전환 후 첫 요청도 다시 생성한다.
- 검증 불합격 후 정리한 초안은 부분 결과이며 정상 완성본 캐시에 저장하지 않는다. 이 상태는 `verification.passed=False`로 유지한다.
- 별도 문서에 기록된 재무 캐시·완성 보고서 캐시 정책은 서로 독립적이다.
