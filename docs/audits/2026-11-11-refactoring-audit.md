## 서비스와 감사 범위

Finsight는 공시·시세·뉴스로 기업 보고서를 만들고, 법령과 업로드 내규를 검색해 근거가 있는 답변을 제공한다. `core / domain / agents / api` 분리는 유지하고, 데이터 갱신·검증·저장·비용 집계의 연결을 우선 수정한다.

README, 의존성·Docker·CI 설정, API 진입점, 문서 저장·검색, 채팅 오케스트레이션, 기업 보고서 생성·검증·캐시, 비용 집계, 주요 재무 계산 및 프론트 흐름을 검토했다. 모든 계산식·차트 함수·평가 데이터를 전수 검증하지 않았다. 실제 DB, 유료 API, 브라우저, 부하 테스트는 이 감사에서 실행하지 않았다.

`audit/finsight-audit-probes.py`는 당시 소스를 담은 JSON에서 함수를 추출하고 외부 객체를 대체해 실행한다. 6개 문제 동작을 확인했지만 현재 `app/`를 직접 검사하지 않으며, 실제 서비스 통합 테스트나 정식 회귀 테스트가 아니다. 특히 해당 스크립트의 성공은 **문제 재현 성공**을 뜻한다.

- **위치:** `backends/app/core/dart/financials.py:57–76`, `backends/app/core/dart/history.py:94–99`.
- **역할:** 기간별 재무제표를 캐시하고 정정 접수번호가 달라지면 갱신한다.
- **문제:** 호출부가 `expected_rcept_no`를 전달하지 않는다. 데이터 없음 응답 `[]`도 만료 없이 저장한다.
- **수정 방향:** 기간에 맞는 최신 접수번호를 연결하고 빈 응답에는 짧은 만료를 적용한다. 과거 분기의 정정 확인 정책도 정한다. 단순히 전체 캐시를 없애지 않는다.
- **영향:** 새 보고서에도 이전 숫자나 데이터 누락이 남을 수 있다. 원문 fallback이 일부 누락을 보완해도 재무 API 캐시의 갱신 문제는 별개다.
- **회귀 기준:** 정상 캐시 재사용, 정정 후 갱신, 빈 응답 후 데이터 공개 시 재조회, 다른 기간·기업 캐시 보존.

- **회귀 기준:** 임베딩 실패·부분 삽입·정상 교체·재시도에서 기존 검색 결과와 메타데이터가 일관되며 다른 문서는 유지된다.

- **수정 방향:** HTTP 요청 경계에서 집계를 시작하고 하위 작업은 공유한다. 보고서 자체 비용 측정은 병렬 작업을 섞지 않도록 범위를 구분한다.
- **영향:** 비용 표시가 작아지고 요청 단위 상한이 분리된다.
- **회귀 기준:** 실제 채팅→보고서 경로의 비용을 정확히 한 번 합산하고 독립 요청끼리는 분리한다. 캐시 적중도 검사한다.

- **회귀 기준:** 동기화 장치로 요청을 겹쳐 남은 한도를 넘지 않는지 확인한다. 시간 지연에만 의존하는 불안정한 테스트는 피한다.

### 7. 업로드 조문 ID가 다른 문서·공식 법령과 충돌함

- **상태/근거 수준:** 수정·회귀 검증 완료. 등록 파일명 기반 upload 전용 ID를 사용한다. 기존 저장 데이터·벡터는 조회 시 새 ID에 연결하며, 구형 벡터의 물리 문서명까지 겹쳐 구분 불가능한 항목은 재등록이 필요하다. 실제 DB에서 문서 분리와 본문 연결을 확인했다([기록](../testing/2026-11-11-remaining-fixes.md)).
- **위치:** `backends/app/core/law/uploads.py:68–95`, `backends/app/core/law/corpus.py:71–75`.
- **역할:** 문서명·조 번호로 검색 결과와 본문을 연결한다.
- **문제:** 공백을 제거한 파일명이 같으면 ID가 충돌한다. 공식 법령과 같은 이름의 업로드도 충돌하고 본문 조회는 공식 법령을 우선한다.
- **수정 방향:** 표시 이름과 내부 문서 ID를 분리하고 업로드용 namespace를 사용한다. 기존 저장 데이터의 전환 방법도 검토한다.
- **영향:** 검색한 문서와 답변의 근거 본문이 달라질 수 있다.
- **회귀 기준:** 공백 차이·같은 이름·공식 법령 이름을 가진 문서를 함께 저장·검색·삭제해 분리됨을 확인한다.

- **문제/영향:** 호스트 IP 없이 공개한 포트와 Weaviate 익명 접근 설정 때문에 방화벽이 허용하면 다른 기기에서 접근할 수 있다.
- **수정 방향:** 로컬 개발 포트를 `127.0.0.1`에 바인딩한다. 필요한 컨테이너 간 연결은 유지한다.
- **회귀 기준:** Compose 유효성, 호스트 로컬 접근과 컨테이너 간 연결을 확인한다.

## Nice to have

### 11. 단일 구현의 캐시 추상 클래스 제거

- **상태/근거 수준:** 미수정. 검토한 소스·테스트·평가 코드에서 `CacheBackend`의 유일한 구현은 `SQLiteCache`다. 제거 직전에 전체 참조를 다시 검색한다.
- **위치:** `backends/app/core/cache.py:10–45`.
- **문제/영향:** 실제 사용 메서드 `peek`, `cost_by_service`도 빠진 추상 인터페이스를 별도로 유지해야 한다. 런타임 버그보다 유지보수 비용 문제다.
- **수정 방향:** 추상 클래스와 관련 import를 제거하고 기존 SQLite 구현을 직접 사용한다.
- **회귀 기준:** 캐시·장부 테스트와 실제 호출부 동작 유지.

## 판단과 검증 한계

전면 재설계보다 데이터 갱신·실패 처리 연결을 작게 수정하는 편이 적합하다. 앞선 대화의 **약 24줄 감소**는 11번만의 추정이며 전체 변경량이 아니다. 오류 처리와 회귀 테스트 추가로 전체 줄 수는 증가할 수 있다. 의존성 제거 제안은 없다.

기존 테스트가 통과하더라도 위 항목을 모두 검증했다는 뜻은 아니다. 각 항목의 정식 재현 테스트로 판단을 재확인하고, 사실과 다르면 이유를 기록해 제외한다. 수정 완료 표시는 변경 커밋 또는 diff와 관련 테스트 결과를 확보한 뒤에만 한다.
