## 운영·호환성 주의

- 업로드 새 조문 ID는 `upload@<인코딩한 저장 파일명>:<조번호>`다. 구형 저장 조문·벡터 ID는 읽기 시 연결한다. 구형 물리 문서명까지 겹쳐 구분 불가능한 문서는 각각 재등록해야 한다. 기존 채팅의 구형 인용은 자동 복구하지 않는다.
- 문서 교체 실패 시 벡터·조문 메타데이터를 보존하지만 업로드 단계 원본 PDF 버전 보관은 하지 않는다. 비활성 세대 청소·전체 재적재 롤백은 별개다.
- 법령 코퍼스 캐시 갱신과 검색 크레딧 직렬화는 단일 프로세스 기준이다. 검색 동시성은 정확한 한도 검사를 위해 줄였다.
- 미검증·불합격 보고서는 재요청 시 다시 생성하므로 비용이 증가할 수 있다. 계산 표·차트의 원천 정확성을 문장 검증이 보장하지는 않는다.
- DB 포트 변경은 기존 컨테이너의 다음 재생성 때 반영된다. 요청 없이 사용자 DB를 초기화하지 않는다.

## 보존한 파일과 작업 원칙

`audit/finsight-audit-probes.py`는 사용자가 이미 stage한 상태이고 JSON 사본은 untracked다. 요청 없이 stage 해제·전체 추가·삭제하지 않는다. 이 임시 스크립트는 당시 소스 사본의 문제 재현용이며 현재 코드의 정식 회귀 테스트가 아니다.

한국어로 설명한다. 코드 수정·삭제에는 ponytail을 적용하고 관련 없는 변경은 하지 않는다. 검증한 작업 단위마다 기존 `[fix]`·`[refactor]`·`[docs]` 컨벤션으로 커밋한다. 실제 수행 검사와 미확인 범위를 구분한다. PR 게시·푸시는 승인되지 않았으므로 하지 않는다. 문서·검사 기록은 Git에 보존하고 일회성 로그는 제외한다.
