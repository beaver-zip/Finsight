## 감사 자료와 정식 테스트의 차이

- `audit/finsight-audit-sources.json`: GitHub에서 읽은 당시 코드의 일부 사본.
- `audit/finsight-audit-probes.py`: 사본에서 함수를 AST로 추출하고 가짜 외부 객체로 문제 동작을 재현하는 스크립트. 사본 파일은 스크립트 옆의 상대 위치로 읽도록 수정했다.
- 이 스크립트의 6개 CONFIRMED는 **문제 동작 재현**이다. 서비스가 정상이라는 뜻이 아니며 현재 `app/`의 수정도 검증하지 않는다. 일부 항목은 작은 동작만 실행했고 전체 호출 경로는 정적 분석이었다.
- 정식 회귀 테스트는 현재 프로젝트 모듈을 import하고 올바른 동작을 요구한다. 버그 수정 전 실패, 수정 후 통과해야 한다. 3번은 현재 모듈을 호출하는 신규 회귀 테스트를 작성했다. 1번도 `test_financial_cache.py`에 회귀 테스트를 작성했다. 2번도 `test_report_verification.py`에 그래프·API 회귀 테스트를 작성했다. 나머지 항목은 아직 미작성이다.
- 기존 `backends/tests/`는 원래 있던 13파일·96함수이며 매개변수 확장 후 이번에 124개 실행·통과했다. 가짜 외부 연결의 통합 테스트와 임시 실제 SQLite 검사도 포함한다.
- `audit/`는 아직 untracked이다. 정식 테스트로 전환하기 전 자동 삭제하지 않는다. 공유 문서는 Git에 넣되 일회성 사본·로그를 전체 `git add .`로 함께 올리지 않는다.
- 로컬 실행 로그는 기존 무시 경로 `_workspace/baseline-2026-11-11/`에 있다.

## 유지할 합의

- 최소 변경, 관련 없는 정리 금지. 재무 계산식·검색 순위·프롬프트는 문제 해결에 필요한 경우에만 변경한다.
- 현재 올바른 결과를 보존하되 알려진 버그를 정답으로 고정하지 않는다.
- 테스트를 통과시키려고 기대값부터 바꾸지 않는다. 무엇을 실행했고 무엇을 못 했는지 구분한다.
- 감사의 약 24줄 감소는 캐시 추상 클래스 제거(11번)만의 추정이다. 전체 수정은 테스트·실패 처리 추가로 코드가 늘 수 있다.
- 검토된 보고서는 `docs/audits/`, 구현 계획은 `docs/plans/`, 검증 기록은 `docs/testing/`에 보존한다. `AGENTS.md`에는 전문을 복제하지 않고 링크를 둔다.
- 사용자가 작업 단위별 커밋을 승인했다. ponytail을 적용하고 검증한 단위마다 `[fix]`, `[refactor]`, `[docs]` 등 기존 형식으로 커밋한다. PR 게시·푸시는 별도 요청이 없으므로 하지 않는다.
