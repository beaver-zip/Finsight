# Finsight 리팩토링·테스트 계획

- 작성일: 2026-11-11
- 기준 커밋: `ca0ecdc1fe2f3707b80007e2cd687a00af01b438`
- 관련: [감사 보고서](../audits/2026-11-11-refactoring-audit.md), [기준선 결과](../testing/2026-11-11-baseline.md), [인수인계](2026-11-11-handoff.md)
- 현재 승인 범위: 문서 저장과 기존 백엔드 테스트·프론트 빌드 실행. 아래 버그 수정과 새 테스트 구현은 아직 시작하지 않았다.

## 원칙

1. 수정 전 기존 테스트와 빌드를 실행해 기존 실패와 새 실패를 구분한다.
2. 구조만 바꾸는 리팩토링은 기존의 올바른 결과를 보존한다. 버그 수정은 잘못된 결과만 의도적으로 바꾼다.
3. 버그는 현재 프로젝트 모듈을 직접 호출하는 테스트로 재현한다. 수정 전에 실패하고 수정 후 통과해야 한다.
4. 실패뿐 아니라 정상 처리·재시도·다른 요청에 대한 영향도 검사한다.
5. 내부 호출 횟수·순서만 고정하지 말고 계산값, 출처, 사용자 결과, 저장 데이터 보존을 검사한다.
6. 고정 입력·날짜와 격리된 DB를 사용한다. 기대값은 근거를 확인하며 기존 버그를 그대로 정답으로 복사하지 않는다.
7. 작은 변경 단위로 관련 검사를 실행하고, 병합 전 전체 기본 테스트와 빌드를 실행한다. 통과 후 변경 없이 반복 실행하지 않는다.
8. 필요한 통합 검사를 실행하지 못했다면 이유와 한계를 명시한다. 단위 테스트 통과만으로 완료를 과장하지 않는다.

## 기존 테스트 구성

`backends/tests/`에는 테스트 파일 13개와 테스트 함수 96개가 있다. 매개변수별 실행 사례 수는 함수 수와 다르다.

| 영역 | 파일 | 현재 보장 범위 |
| --- | --- | --- |
| 재무·보고서 | `test_domain_finance.py`, `test_report_v2.py` | 고정 입력의 계산·표시·렌더링 |
| 공시 | `test_original.py`, `test_segments.py` | 원문·부문 표 파싱, 분기 값 처리 |
| 법령 | `test_law_parse.py`, `test_annex_table.py`, `test_legal_answer.py` | 조문·위임·별표·인용 처리 |
| 뉴스·날짜 | `test_news_rank.py`, `test_dates.py` | 순위·중복·커버리지·날짜 해석 |
| 비용·캐시 | `test_budget.py` | 단가, 순차 상한 검사, SQLite 캐시 만료 |
| 문서 | `test_documents.py` | 테스트용 HTTP 요청과 가짜 벡터 DB로 문서 왕복 |
| 채팅 | `test_orchestrator.py` | 실제 그래프와 가짜 LLM·외부 작업으로 상태 전이 |
| 평가 코드 | `test_eval.py` | 점수·통계 함수 자체의 정확성; AI 품질 평가 실행과 다름 |

`conftest.py`는 테스트별 임시 SQLite를 생성한다. `pytest.ini`는 `tests/`를 탐색하고 비동기 테스트를 자동 처리하며 기본 실행에서 `live` 표시를 제외한다. 실제 Weaviate·Neo4j와 브라우저를 연결하는 테스트는 별도 보강 대상이다. 프론트에는 현재 동작 테스트 명령이 없고 CI는 타입 검사·빌드를 실행한다.

## 테스트 단계와 실행 시점

| 단계 | 검사 대상 | 시점 |
| --- | --- | --- |
| 단위 | 재무·파싱·ID·캐시·검증 정책의 작은 규칙 | 관련 변경마다 |
| 통합 | API↔저장소, 채팅↔보고서↔비용, 서버 재적재 | 해당 연결 변경 및 PR 검증 |
| E2E | 실제 브라우저↔백엔드↔테스트 저장소 | 핵심 사용자 흐름 변경·병합 전 |
| AI 평가 | 근거·핵심 사실·수치·거절·검색 품질 | 프롬프트·검색·모델·근거 전달 변경 시 |

회귀 테스트는 위 단계와 별개의 목적이다. 모든 단계에서 이전 오류의 재발을 막는 테스트를 둘 수 있다. 단위·통합 테스트는 외부 유료 API 응답을 고정해도 되지만, 검사하려는 내부 연결 자체를 가짜로 대체하지 않는다. 예를 들어 비용 누락 테스트에서는 실제 보고서 호출 경로를 유지하고 외부 API만 대체한다.

실제 DB 검사는 기존 사용자의 볼륨·데이터를 쓰지 않는다. E2E는 유료 API를 고정 응답으로 대체할 수 있으나 어디를 대체했는지 명시한다. 실제 API smoke test와 AI 평가는 비용·비결정성 때문에 기본 CI와 분리한다. 문장 전체 일치보다 사실·숫자·인용·검증 상태를 평가한다.

## 권장 구현 순서와 완료 기준

| 순서 | 감사 번호 | 추가할 회귀 검사 |
| --- | --- | --- |
| 1 | 3 문서 교체 | 삽입·임베딩 실패에도 이전 검색·메타데이터 보존; 정상 교체·재시도·다른 문서 유지 |
| 2 | 1 재무 캐시 | 정정 접수번호 갱신, 빈 캐시 재조회, 정상 캐시 재사용, 기간·기업 분리 |
| 3 | 2 검증 실패 | 미검증 보고서의 정상 캐시 금지; HTML/JSON/SSE의 일관된 상태 |
| 4 | 5·6 비용·동시성 | 하위 비용 정확히 한 번 합산; 요청 간 격리; 동시 검색 상한·실패 복구 |
| 5 | 4·7 법령·문서 ID | 서버 재시작 없이 본문 갱신; 동명이름·공식 법령과 분리; 기존 데이터 전환 |
| 6 | 8·9 프론트 | 저장 파일명 전달, 부분 거절, SSE 정상 완료·조기 EOF·취소; 사용자 E2E |
| 7 | 10·11 설정·정리 | Compose 로컬 바인딩·연결, 캐시 추상화 제거 후 기존 기능 보존 |

각 변경은 관련 테스트가 통과하고 실제 연결의 필요 검사가 끝난 뒤 완료로 표시한다. 테스트 기대값 변경은 의도한 동작 변경일 때만 근거를 적는다. 새 아키텍처나 의존성은 먼저 도입하지 말고 실제 해결에 필요한 최소 범위를 선택한다.

## 실행 명령

기존 기본 검사:

```bash
cd backends
.venv/bin/python -m pytest -q
# 특정 기능 작업 중에는 해당 파일만 먼저 실행
.venv/bin/python -m pytest tests/test_documents.py -q

cd ../frontends/corp-advisor--app
npm run build
```

실제 외부 API 표시가 있는 테스트를 실행하는 경우 `pytest -m live`로 선택한다. 이는 현재 실행했다는 뜻이 아니며 필요한 자격증명·비용 범위를 먼저 확인한다. 아직 없는 프론트 테스트·E2E 명령을 실행 가능한 것으로 문서화하지 않는다.

## 임시 감사 자료의 전환

`audit/finsight-audit-sources.json`은 당시 코드 사본이고 `audit/finsight-audit-probes.py`는 사본의 문제 동작을 확인한다. 현재 코드 수정 후에도 옛 문제를 재현할 수 있어 회귀 보호가 아니다. 유효한 사례를 현재 모듈을 import하는 정식 테스트로 옮기고, 필요한 근거를 남긴 후 임시 자료를 정리한다. 이번 문서·기준선 단계에서는 해당 파일을 삭제하지 않는다.
